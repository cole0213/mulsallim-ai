# 물살림 AI 실사용 완성도 보강

## 핵심 요약

물살림 AI의 제출·시연 중심 화면을 실제 농업인과 현장 담당자의 반복 과업 중심으로 재설계했다. 핵심은 AI 기능을 늘리는 것이 아니라, `지역 선택 → 관측 근거 → 이번 주 행동 → 공유·재확인`으로 끝나는 안전한 사용 흐름이다.

## 기록

### 사용자 중심 랜딩과 실제 대시보드 분리  <!-- (2026-07-24) -->

- 새 랜딩: `mulsallim-public-v2.html`
  - 지역 선택을 첫 행동으로 두고, 저수지 코드를 사용자에게 노출하지 않는다.
  - 기술 설명보다 현재 확인·판단·공유의 실제 효용을 먼저 설명한다.
  - 관심 저수지와 최근 확인 항목을 다음 방문의 바로가기으로 제공한다.
- 새 실제 대시보드: `mulsallim-dashboard-practice.html`
  - 기존 분석 화면의 작물 가정 시나리오·동일 지역 우선순위 비교를 첫 사용 흐름에서 숨겼다.
  - 이유: 실측되지 않은 가정을 같은 층위에서 보여 주면 농업인의 핵심 판단을 흐릴 수 있기 때문이다.
  - 대신 위험 단계별 현장 점검 체크리스트, ADMS 공식 정보 연결, 기기 내 현장 메모, 공유 브리핑, 재확인 일정 저장을 제공한다.

### 신뢰를 위한 제품 원칙  <!-- (2026-07-24) -->

- KRC 관측일·관측기간·누락일·데이터 신뢰도를 화면에 공개한다.
- AI는 이상 패턴을 설명하는 보조 근거이며, 가뭄 예보·공식 경보·급수 배분 결정을 대체하지 않는다.
- 성능이 기준선보다 낮았던 Gradient Boosting 후보는 배포하지 않는다. 관련: [[AI 모델 검증]].
- 현장 메모는 현재 브라우저의 로컬 저장소에만 저장된다는 점을 명시한다. 서버 전송·공유 기능으로 확대할 때는 동의, 보관 기간, 접근 권한 설계가 선행되어야 한다.

### 검증 결과  <!-- (2026-07-24) -->

- `mulsallim-public-v2.html`, `mulsallim-dashboard-practice.html`, 관련 JavaScript의 문법 검사를 통과했다.
- 로컬 서버 `http://localhost:4182`에서 새 정적 파일 4종의 HTTP 200 응답을 확인했다.
- KRC 코드 조회 API로 충청남도 저수지 목록의 실제 응답을 확인했다.
- 브라우저 시각 자동화는 현재 로컬 실행 환경의 Windows sandbox 오류로 수행하지 못했다. 시연 전 브라우저에서 지역 선택·저수지 선택·메모·브리핑·일정 저장을 수동 점검한다.
