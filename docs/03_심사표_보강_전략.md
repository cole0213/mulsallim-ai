# 물살림 AI 심사표 보강 전략

## 1. 전략 변경 이유

KRC 농업가뭄관리시스템은 이미 저수율 현황·저수율 예측·저수율 지도·농민 행동요령을 제공한다. 따라서 단순히 저수율을 예측·조회하는 서비스는 기존 서비스와 중복으로 보일 위험이 있다.

물살림 AI의 역할을 다음처럼 재정의한다.

> **가뭄 전환점 예측과 공동 절수 시나리오를 통해, 저수율 정보를 실제 물관리 행동으로 바꾸는 서비스**

## 2. 최종 작품 정의

### 작품명

**물살림 AI: 가뭄 전환점 예측 및 공동 절수 시나리오 서비스**

### 핵심 가치

- 기존 시스템이 `현재 상황`과 `예측값`을 제공한다면,
- 물살림 AI는 `어떤 행동을 선택하면 안전일이 얼마나 달라지는지`를 비교한다.

### 핵심 질문

1. 이 저수지는 언제 관심·주의 단계로 전환될 가능성이 높은가?
2. 권역의 용수 사용량을 10% 또는 20% 줄이면 안정 기간은 며칠 연장되는가?
3. 어떤 저수지·수혜구역부터 점검·절수 협의를 시작해야 하는가?

## 3. 심사 항목별 보강

| 평가 항목 | 배점 | 심사자가 확인할 증빙 | 물살림 AI 보강안 |
|---|---:|---|---|
| 활용성 | 30 | KRC 데이터 활용의 필연성·공익성 | KRC 수위 API의 일자별 저수율과 가뭄지도·시설제원·수혜면적을 위험·시나리오 입력으로 명시. 실제 API 호출 로그와 기준시각 표시 |
| 창의성 | 20 | 기존 서비스와 다른 문제 해결 | 예측값 자체가 아닌 `절수율별 안전일 연장 효과`와 `가뭄 전환점`을 제공. 농민·관리자가 같은 권역 시나리오를 공유 |
| 사업성 | 20 | 도입 주체·운영 구조·확장성 | KRC 농촌용수 관리 업무의 보조 모듈 → 지자체 가뭄 대응반 → 농민 모바일 알림 순으로 확장. 시범 권역 5~10개 저수지부터 검증 |
| AI 활용성 | 20 | 모델 적정성·편의성·유용성 | 365일 수위 이력 기반 7일 예측, 급감 이상탐지, 롤링 검증의 MAE/MAPE·경보 F1 제시. LLM은 설명 전용 |
| 완성도 | 10 | 논리·발표 전달력 | 문제-데이터-모델-시나리오-효과-도입 순서의 7분 데모와 실제 URL·API 로그·오류 고지 |

## 4. 기존 서비스와의 차별성 문장

> 기존 서비스가 저수율 현황과 예측을 제공하는 데 비해, 물살림 AI는 예측 결과를 토대로 절수 수준별 안전일 연장 효과와 전환 시점을 시뮬레이션한다. 즉, 정보를 제공하는 서비스를 넘어 농민과 관리자가 공동으로 물관리 결정을 내리도록 돕는다.

## 5. AI 검증 계획

### 데이터셋

- 저수지별 일자·수위·저수율: KRC 농촌용수 저수지 수위정보 조회 API
- 보조 특성: 평년 대비 저수율, 가뭄 단계, 단기 강수량, 유효저수량·수혜면적
- 학습 구간: 저수지별 최근 365일 이력

### 모델

| 과업 | MVP 모델 | 비교 기준 | 평가지표 |
|---|---|---|---|
| 7일 저수율 예측 | Gradient Boosting 또는 Prophet | 최근값 유지, 7일 이동평균 | MAE, MAPE |
| 급감 탐지 | 변화율 규칙 + Isolation Forest | 변화율 임계값 단독 | Precision, Recall, F1 |
| 절수 시나리오 | 저장 여력·수요 탄력 기반 시뮬레이션 | 현 상태 유지 | 안전일 연장량 |

### 검증 원칙

- 미래 데이터를 학습에 섞지 않는 롤링 시계열 검증을 사용한다.
- 실제 API 데이터가 확보되기 전에는 성능 수치를 기획서에 쓰지 않는다.
- 모델 결과와 근거 변수는 화면에서 함께 표시한다.

## 6. 사업·확산 모델

1. **시범 운영**: 하나의 KRC 지사 관할 저수지 5~10개를 대상으로 API 데이터 연동 및 담당자 피드백 수집
2. **업무 도입**: KRC·지자체 가뭄 대응 담당자의 일일 점검 우선순위 및 절수 협의 자료로 활용
3. **농민 확산**: QR 기반 모바일 웹에서 권역·수원 선택 후 행동지침 확인
4. **고도화**: 수혜구역·급수량·작물별 수요 데이터 연계 후 농경지 단위 처방 제공

## 7. 기획서에서 삭제하거나 낮춰야 할 표현

- `기존 서비스에 없는 저수율 예측` → 삭제
- `수질 안전 판정` → 수질 데이터 연동 전까지 삭제
- `실시간 AI 예측` → 실제 API 연동·모델 검증 뒤에만 사용
- `자동 관개 제어` → 구현·권한 범위 밖이므로 삭제
