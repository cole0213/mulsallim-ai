# 물살림 AI 실사용 재설계 감사

## 결론

기존 랜딩은 공모전 소개와 기능 설명에 치우쳐 있었고, 실제 사용자가 첫 방문에 해야 하는 “내 지역 확인”과 재방문의 “관심 저수지 바로 보기”가 약했다. 최종 사용자 진입은 `mulsallim-user.html`, 실제 서비스는 `mulsallim-service.html`로 재구성한다.

## 사용자별 핵심 과업

| 사용자 | 실제 질문 | 서비스의 첫 답 |
| --- | --- | --- |
| 농업인 | 우리 지역 물 상황이 평소와 다른가? | 최신 관측일·저수율·7일 변화·누락 안내 |
| 농업인 대표 | 지금 절수 협의를 꺼내야 하는가? | 이번 주 행동 문장·전환 신호 근거·절수 선택 비교 |
| 현장 담당자 | 어디부터 확인하고 누구와 공유할까? | 동일 시·군 우선순위·TXT 브리핑 |

## 제거 또는 후순위화한 것

- 랜딩의 기술 용어·AI 모델 설명·점수 나열: 첫 화면에서 제거. 사용자는 먼저 지역을 선택한다.
- “관제 화면” 포지셔닝: 현장 담당자 전용으로 오해될 수 있어 제거.
- 예측 모델 성능 수치: 실제 판단 흐름의 하단 검증·정보 영역으로만 유지.
- 작물·면적 시나리오: 첫 진입에서 강요하지 않고 저수지 선택 뒤 필요한 사용자가 여는 보조 도구로 유지.

## 반복 사용 흐름

1. 첫 방문: 시·도와 시·군·구 선택 → 저수지 후보 → 원자료 기반 판단.
2. 관심 저수지 저장: 브라우저에 저장.
3. 재방문: 랜딩의 “저장한 관심 저수지”에서 바로 서비스 진입.
4. 변화 발생: 전환 신호·근거·주의선 도달 추정 확인 → 지역 비교 → TXT 브리핑 공유.

## 신뢰 원칙

- 랜딩부터 공식 예경보 비대체·데이터 한계를 명시.
- 점수·시나리오보다 관측일·누락·근거를 먼저 보여준다.
- AI는 판단을 대신하는 장식이 아니라, 최근 변화의 이례성을 설명하는 보조 근거로만 제시한다.

## 최종 경로

- 사용자 시작: `http://localhost:4182/mulsallim-user.html`
- 실제 서비스: `http://localhost:4182/mulsallim-service.html`
