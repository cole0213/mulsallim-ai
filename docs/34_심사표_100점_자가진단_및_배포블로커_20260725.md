# 물살림 AI — 심사표 100점 자가진단 · 배포 블로커 브리핑

> 작성: 2026-07-25 (야간 자율 세션) · 관련: [[33_물살림AI_100점_공개배포_로드맵]], [[03_심사표_보강_전략]], [[27_다지역_시간분리_AI검증_보고서]]

## TL;DR (아침에 이것부터)

1. **서비스 콘텐츠·UX는 이미 강함(체감 85점대).** 라이브 KRC 데이터, 정직한 AI 프레이밍, 의사결정 흐름이 심사표에 잘 맞는다. 직접 오리진(`http://nmlab16.korea.ac.kr:4184/`)에서 전 기능 정상 확인함.
2. **HTTPS 공개 데모(`https://mulsallim-ai.pages.dev`)는 지금 판정단에게 보여주면 안 된다.** 두 가지가 깨져 있다:
   - **블로커 A (내가 못 고침 — 서버 접근 필요):** `/api/*` → **HTTP 522**. Cloudflare 엣지가 오리진 `nmlab16.korea.ac.kr:4184`에 도달하지 못함(비표준 포트 4184 + KU 방화벽).
   - **블로커 B (내가 고침):** 지역선택 폼이 **빈 채로 뜸**. `_headers`의 CSP가 `unsafe-eval`을 막는데 지역선택 로더가 `eval()`을 씀. → 빌드 시점에 eval 제거로 해결.
3. **1순위 아침 작업 = 블로커 A.** 아래 "블로커 A 해결" 절의 cloudflared 터널 5분 작업이면 HTTPS 데모가 진짜로 살아난다.

## 검증된 진단 (추측 아님, 실측)

### 블로커 A — Cloudflare가 오리진에 도달 못 함 (522)

| 테스트 | 결과 | 의미 |
|---|---|---|
| `https://mulsallim-ai.pages.dev/` | 200, 0.05s | 정적 호스팅 정상 |
| `https://.../api/health` | **522**, 19.4s 타임아웃 | Function→오리진 연결 실패 |
| 생 IP(`163.152.223.16`) 프록시 | 즉시 403 `error 1003` | Cloudflare가 raw-IP subrequest 거부 |
| 호스트명(`nmlab16.korea.ac.kr:4184`) 프록시 | 522 타임아웃 | 1003은 통과, **포트 4184 도달 실패** |
| 내 PC→오리진 포트 8080/8443 | 죽어있음(000) | 표준 대체포트 안 열림 |
| 내 PC→오리진 포트 4184 | 200 | 오리진 앱 자체는 정상 |

**결론:** 외부에서 열린 유일한 포트는 4184인데 Cloudflare는 비표준 포트 4184의 오리진에 못 붙는다(포트 제한 또는 KU 방화벽의 Cloudflare IP 차단). 표준 포트(80/443)는 KU 상위망이 외부 인입을 막아 LE 인증서도 실패했던 그 이유 그대로.

### 블로커 B — CSP가 지역선택 eval을 막음 (내가 수정)

- 라이브 진입 체인이 런타임에 옛 버전 파일을 fetch→문자열치환→`document.write()`/`eval()` 하는 "러시안 인형" 구조.
- `mulsallim-public-county-v12-loader.js`가 `(0,eval)(v5소스)`를 실행 → CSP `script-src 'self' 'unsafe-inline'`(unsafe-eval 없음)에 **차단**.
- 실측: 오리진에선 시·도 드롭다운 17개, **Pages에선 0개(빈 폼)**. `document.write` 인라인 스크립트는 CSP 통과하나 `eval`만 막힘.
- 오리진은 CSP 헤더를 아예 안 보내서(nosniff만) eval이 됐던 것. Pages는 `_headers`의 엄격 CSP 적용.
- **수정 방향:** 빌드(`build-pages.mjs`)에서 로더를 v5.js 해석본(플랫 스크립트)으로 생성 → eval 제거, 엄격 CSP 유지. (보안 약화 없이 해결 — 완성도 가점)

## 블로커 A 해결 — 아침 5분 작업 (권장안)

오리진 서버 `nmlab16.korea.ac.kr`에서 아래 실행. cloudflared 터널은 **오리진이 Cloudflare로 아웃바운드 연결**을 열어서 인입 방화벽·포트 제한을 우회하고, 무료이며 Zero Trust 결제도 필요 없다.

```bash
# 오리진 서버에서 (SSH 접속 후)
# 1) cloudflared 설치 (Debian/Ubuntu 예시)
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
chmod +x /usr/local/bin/cloudflared

# 2) 빠른 검증용 임시 터널 (즉시 https URL 발급, 프로세스 살아있는 동안 유효)
cloudflared tunnel --url http://localhost:4184
#  -> https://<랜덤>.trycloudflare.com 이 발급됨. 이걸로 즉시 동작 확인 가능.
```

검증되면 **고정 주소를 위한 named tunnel**로 승격(재부팅에도 유지):

```bash
cloudflared tunnel login                       # 브라우저에서 Cloudflare 계정 인증
cloudflared tunnel create mulsallim            # 터널 생성 → <TUNNEL_ID>
# ~/.cloudflared/config.yml 작성:
#   tunnel: <TUNNEL_ID>
#   credentials-file: /root/.cloudflared/<TUNNEL_ID>.json
#   ingress:
#     - hostname: mulsallim-origin.<네도메인>   # 도메인 있으면
#       service: http://localhost:4184
#     - service: http_status:404
cloudflared tunnel route dns mulsallim mulsallim-origin.<네도메인>
cloudflared service install                    # systemd 등록(재시작 유지)
```

그 다음 **Cloudflare Pages 환경변수**만 터널 주소로 바꾸면 끝:
`MULSALLIM_ORIGIN = https://<터널주소>` → Pages 재배포.
(Function 코드의 DEFAULT_ORIGIN은 이미 호스트명으로 고쳐뒀으나, 터널 쓰면 env var가 정답.)

### 대안 옵션 (트레이드오프)

- **B안 — Pages Function이 KRC API 직접 호출:** 오리진 서버를 빼고 Function이 `data.go.kr` KRC API를 직접 호출. HTTPS 즉시 동작. **단점:** KRC 키를 Cloudflare 암호화 secret에 넣어야 함(로드맵의 "키는 오리진에만" 원칙과 충돌) + 협의카드/피드백 파일 저장 기능을 Cloudflare KV/D1로 옮겨야 함. 규상 결정 필요 — 나 혼자 안 했음.
- **C안 — 오리진을 표준 개방포트로:** KU 망이 외부 인입 여는 포트가 있으면 그쪽으로 앱 이전. 방화벽 정책 확인 필요.

**권장: A안(cloudflared named tunnel).** 원칙 유지 + 무료 + 고정주소 + 최소 변경.

## 심사표 자가진단 (냉정하게)

> 근거: 오리진 라이브에서 충남 공주시 경천(양화) 저수지로 전 흐름 실사용 확인. AI 검증 JSON·모델카드 확인.

| 항목 | 배점 | 체감 | 강점(있는 것) | 100점 격차(부족) |
|---|---:|---:|---|---|
| 활용성 | 30 | ~26 | 실 KRC 저수율/수위/관측일 라이브, 코드 은닉 지역선택, 공익적 의사결정 흐름 | HTTPS 공개 데모가 실제 동작해야(블로커 A). 지역 선택 성공률 등 사용 근거 |
| 창의성 | 20 | ~18 | "숫자 조회"가 아닌 "변화 근거→현장 협의" 재정의, AI 한계 공개가 화면에 명시 | 경쟁/기존 서비스 대비표를 화면/발표에 1장으로 |
| 사업성 | 20 | ~14 | 확장 로드맵(지사→지자체→농민), 반복사용 설계 | **파일럿 실적 0건.** 도입주체·운영구조를 발표자료에 구체화. 정직하게 "진행 중"으로 |
| AI 활용성 | 20 | ~17 | **정직한 검증**: GBM이 기준선(전일값유지)보다 MAE 나빠 배포 제외, 이상탐지는 근거용, 다지역 시간분리 검증 | 성능표를 화면 모델카드에 그대로 노출(현재 문서에만). 자동경보 배제 이유 강조 |
| 완성도 | 10 | ~6 | 정직성·접근성 배려·오류 문구 | **HTTPS 데모 깨짐(A+B).** repo가 v2~v12 + eval 난립 → 정리 필요 |

**체감 합계 ~81/100.** 콘텐츠는 이미 좋고, **격차의 절반 이상이 "배포·완성도"에 몰려 있다.** 즉 블로커 A만 풀리고 repo가 깔끔해지면 90점대 진입이 현실적.

### 정직성 원칙 (지킬 것)
없는 파일럿 실적·근거 없는 성능 수치를 지어내지 않는다. "진행 중"으로 정직하게 두는 편이 심사에서 더 강하다. 지금 화면의 정직한 AI 프레이밍이 오히려 차별점이다.
