# 물살림 AI 제출 기준서

이 문서는 공모전 한글 양식, 기획서, 웹 MVP, 발표자료가 같은 사실과 기능을 말하도록 관리하는 단일 기준 문서다.

## 1. 공모전 적합성

| 한글 양식 항목 | 확정 내용 | 구현 대응 |
|---|---|---|
| 참가분야 | 서비스개발 | 웹 서비스 |
| 주제 | 안전강화 | 농업용수 안전·관개 의사결정 |
| 작품명 | 물살림 AI: 농업용수 안전일 예측 및 관개 의사결정 서비스 | 랜딩·대시보드 제목 동일 |
| KRC 활용 데이터 | 농촌용수 저수지 수위정보 조회, 가뭄지도 정보 | 저수율·평년 대비·가뭄 단계·수혜면적 분석 |
| 타기관 데이터 | 기상청 단기예보, 농촌진흥청 작물별 용수 정보 | 단기 강수·작물별 처방 보조 |
| 서비스 형태 | 웹(Web) | `index.html`, `dashboard.html` |
| 실행 증빙 | 실제 배포 URL, 화면 캡처, API 호출 로그 | GitHub Pages/Netlify/Vercel 배포 예정 |

## 2. 제출 서류에서 지켜야 할 사실성

- 시연 데이터 상태에서는 `실시간`, `정확도`, `AI 예측 완료`라는 표현을 쓰지 않는다.
- 현재 구현은 `KRC 공공데이터 API 연동 구조를 반영한 시연 MVP`라고 표기한다.
- 실제 API 연동 뒤에만 `실시간 KRC 데이터 기반`으로 바꾼다.
- 안전일은 재난 경보나 자동 관개 명령이 아닌, 사용자의 판단을 돕는 `의사결정 보조지표`다.
- 수질 데이터가 연동되지 않은 상태에서는 수질 안전을 판단한다고 주장하지 않는다.

## 3. 한글 기획서 목차와 웹 화면 연결

| 기획서 항목 | 웹 증빙 화면 | 발표 시 보여줄 장면 |
|---|---|---|
| 서비스 개요 | 랜딩 첫 화면 | 수위 숫자를 행동으로 번역한다는 문제 정의 |
| 주요 내용 | 운영 대시보드 요약·저수지 목록 | 위험 저수지 우선순위 |
| AI·데이터 활용성 | 저수지 상세의 위험 근거·추세 그래프 | 왜 위험으로 판단했는지 설명 |
| 차별성 | 관개 처방 시뮬레이터 | 수위 조회가 아닌 관개 결정 지원 |
| 추진성과 | 점검표 내려받기·관리자 처방 | 현장 점검 우선순위 생성 |
| 추가 개방 필요 데이터 | 데이터 연동 안내 | 수혜구역·급수량·과거 이력 요청 |

## 4. 제출 전 변경 체크

- [ ] 대표자·팀원·서명·연락처를 실제 정보로 입력
- [ ] 실제 배포 URL 반영
- [ ] API 데이터 기준시각 표시
- [ ] 데모 데이터 표기를 실데이터 표기로 교체
- [ ] 발표 화면에서 개인정보 및 API 인증키 노출 여부 점검
