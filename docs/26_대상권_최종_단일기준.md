# 물살림 AI — 대상권 제출·시연 단일 기준

> 최종 갱신: 2026-07-24  
> 이 문서는 현재 제출 원고·시연·개발 판단의 **유일한 최신 기준**이다. 이전 `00~25` 문서는 작성 과정의 참고 기록이며, URL·기능·정량 주장 충돌 시 이 문서를 우선한다.

## 1. 한 문장 정의

**물살림 AI는 사용자가 저수지 코드를 몰라도 우리 지역의 농업용수 변화를 확인하고, 근거가 남는 현장 확인·협의까지 이어가게 하는 KRC 공공데이터 기반 의사결정 보조 서비스다.**

공식 가뭄 경보, 급수 지시, 저수지 운영 결정을 대체하거나 자동화하지 않는다.

## 2. 심사 기준과 증거

| 평가항목 | 배점 | 제출·시연에서 보여줄 객관적 증거 |
|---|---:|---|
| 활용성 | 30 | 시·도 → 시·군·구 → 저수지 선택, 코드 비노출, 최신 KRC 관측일·원자료·무관측 안내, 그래프/툴팁/행동 제안 |
| 창의성 | 20 | 단순 조회를 `전환 신호 → 현장 행동 → 익명 협의 카드`로 연결. 공개 링크에는 상태 변경권한을 주지 않고 생성 기기만 관리 |
| 사업성 | 20 | 농업인·KRC 현장 담당자·지자체의 공동 확인 흐름, 개인정보 최소화, 30일 보관, 파일럿 KPI와 확장 API 구조 |
| AI 활용성 | 20 | 저수율·7일 변화·관측 연속성 기반 설명 가능한 전환 신호, 오프라인 이상 패턴 탐색, 성능 미달 예측 모델의 배포 보류와 모델카드 |
| 완성도 | 10 | API 키 서버 환경변수, 입력 범위 검증, 5분 캐시·요청 제한·12초 타임아웃, 모바일 반응형·키보드 그래프·공유 권한 분리·회귀 테스트 |

## 3. 실제 배포 기준 화면

로컬 시연 기본 주소: `http://localhost:4184/`

| 목적 | 최신 경로 | 반드시 설명할 점 |
|---|---|---|
| 관심 유도·지역 진입 | `/` → `mulsallim-public-county-v7.html` | 랜딩은 기능 나열이 아니라 ‘내 지역을 바로 확인’하는 진입점 |
| 실사용 대시보드 | `mulsallim-dashboard-county-v7.html` | 최신 저수율·7일 변화·위험 근거·그래프·다음 행동·현장 메모 |
| 협의 카드 | `mulsallim-action-card.html?id=...` | 공개 링크는 읽기 전용, 상태 변경은 생성자 전용 키가 있어야 가능 |
| AI 모델카드 | `mulsallim-ai-model-card.html` | 무엇을 제공/보류하는지, 공식 판단을 대체하지 않는 이유 |

## 4. 데이터와 기능 경계

- 출처: 한국농어촌공사 `농촌용수 저수지 수위정보` REST API.
- `county` 조회는 최근 최대 31일만 허용하고, 개별 저수지 상세 이력은 최대 366일로 제한한다.
- 위치 기반 선택은 최근 관측값에서 실제 관리 시·군·구만 보여준다. 관측 대상이 없는 지역은 빈 목록을 숨기지 않고 `조회 대상 없음`으로 안내한다.
- KRC API 인증키는 브라우저·문서·저장소에 넣지 않고 서버 환경변수로만 관리한다.
- API는 요청 제한(분당 120회/IP), 5분 캐시, 12초 타임아웃을 적용한다.

## 5. AI 주장 원칙 — 과장 금지

현재 대시보드의 전환 신호는 **설명 가능한 분석 신호**다. 최신 저수율, 단기 변화, 관측 연속성을 근거로 ‘현장 확인 우선순위’를 제시한다. 이 신호를 미래 가뭄 예측 또는 공식 경보로 표현하지 않는다.

탑정저수지 365일 이력으로 Isolation Forest 기반의 이상 전환 패턴 탐색을 수행했지만, 이는 과거 패턴 대비 희소성을 보는 보조 근거다. 7일 후 저수율 예측 후보는 기준선보다 성능이 낮아 배포하지 않았다. 이 결정은 약점이 아니라, **성능이 불충분한 AI를 서비스 기능으로 포장하지 않는 배포 원칙**이다.

AI 예측 기능은 아래 네 게이트를 모두 통과할 때만 제한적으로 추가한다.

1. 강수·수요·급수·가뭄 이력 등 설명변수 확장
2. 시간 분리 검증과 지역·계절별 일반화 점검
3. 기준선 대비 정밀도·재현율·오경보율 공개
4. 현장 파일럿의 행동 완료율·불필요 경보율 확인

## 6. 협의 카드와 개인정보 설계

- 카드에는 저수지명, 일반 지역명, 관측일, 저수율, 다음 확인 항목만 넣는다.
- 이름·전화번호·정확한 농지 주소 입력을 금지하고, 입력값에서 제어문자와 HTML 태그를 제거한다.
- 공개 카드 URL에는 상태 변경 키를 포함하지 않는다.
- 생성자에게만 발급되는 비공개 키로 `확인 요청 → 현장 확인 중 → 확인 완료` 상태를 변경한다.
- 카드는 30일 뒤 자동 삭제한다. 이는 영구 커뮤니티가 아니라 단기 현장 협의를 위한 최소 보관 설계다.

## 7. 파일럿 설계와 측정값

아직 ‘파일럿 완료’라고 주장하지 않는다. 제출 시에는 다음 계획을 제시한다.

| 구분 | 제안 |
|---|---|
| 대상 | KRC 지역부서 1곳, 수리계/농업인 대표 10~20명, 4주 |
| 시나리오 | 저수율 또는 급격한 하락 신호 발생 → 관측 재확인 → 급수 여력·현장 상태 협의 카드 기록 |
| 핵심 KPI | 지역 선택 후 첫 결과 도달시간, 카드 생성·확인 완료율, 확인까지 걸린 시간, 불필요 경보 비율, 사용자 이해도 |
| 성공 기준 | 첫 결과 도달 중앙값 2분 이내, 카드 확인 완료율 70% 이상, 사용자가 근거/주의문을 이해했다고 응답 80% 이상 |
| 중단 기준 | 개인정보 오입력 반복, 데이터 지연으로 의사결정 혼선, 불필요 경보가 현장 부담을 유발하면 기능 범위를 축소하고 재검증 |

## 8. 5분 시연 순서

1. 기본 주소에서 지역을 고른다. 예: 제주특별자치도 → 실제 KRC 관측 시·군·구.
2. 저수지를 선택한다. 이용자가 코드 입력 없이 결과로 들어감을 강조한다.
3. 최신 관측일, 저수율, 7일 변화, 차트 툴팁, 위험 근거와 ‘다음 행동’을 보여준다.
4. 현장 메모와 협의 카드를 생성한다. 공개 링크와 생성자 상태 변경 권한이 분리됨을 보인다.
5. 모델카드를 열어 자동 예측을 과장하지 않고 배포 보류·검증 게이트를 공개했음을 설명한다.

## 9. 최종 검증 결과

2026-07-24 로컬 v7 회귀 테스트에서 다음을 확인했다.

- 건강 상태 및 KRC 키 서버 설정 확인
- 제주 지역 조회 30건, 선택 저수지 상세 이력 23건 조회
- 서울 무관측을 오류가 아닌 `noData` 응답으로 처리
- 기본 화면·대시보드·모델카드·협의 카드 화면 HTTP 200
- 협의 카드 공개 조회에서 관리 키가 노출되지 않음
- 관리 키 없는 상태 변경 요청은 HTTP 403으로 차단

관련 테스트: `smoke-test-target-v7.js`

## 10. 제출 전 금지 사항

- 과거 v2~v5 URL 또는 예전 “최종본” 안내를 제출물에 쓰지 않는다.
- 성능 검증되지 않은 미래 예측·가뭄 예보·정확도 수치를 주장하지 않는다.
- 파일럿을 진행하지 않았으면 완료 사실처럼 쓰지 않는다.
- API 키, 공개 링크의 생성자 관리 키, 사용자 개인정보를 문서·화면·발표자료에 넣지 않는다.
